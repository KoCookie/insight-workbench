# Research Notes

## Current Product Thinking

Insight Workbench should be broad enough for general industry and company research, but deep enough to support consulting-style analysis.

The product should avoid becoming a simple AI Q&A wrapper. Its value should come from persistent research boards, source management, evidence-grounded insight cards, structured frameworks, dashboards, and outputs.

## Key Product Decisions

### 1. Use topic boards instead of heavy projects

The backend can use a project model, but the user-facing language should feel lighter. Users should feel they are tracking a topic, company, or industry.

### 2. Use one workflow with progressive depth

Do not split the product into separate modules for casual users, interns, and consultants. Everyone starts from the same topic board. Advanced users can go deeper through analysis tools and evidence management.

### 3. Make AI an embedded assistant

AI should appear through product actions:

- generate blueprint
- recommend sources
- extract facts
- create insight cards
- build analysis artifacts
- update dashboard
- export outputs

The main surface should not be a chat window.

### 4. Make the first heavy user action source collection

Users should not need to do heavy work during blueprint generation. The first meaningful user effort is adding or confirming sources, guided by the AI-generated source checklist.

## Airline Revenue Management Demo

The first validation case will use an airline revenue management AI transformation project.

Existing human research outputs include:

- industry overview
- value chain analysis
- revenue management focus
- AI technology to business scenario matrix
- maturity assessment
- ancillary revenue AI matching matrix
- demand forecasting AI transformation roadmap

The demo should test whether Insight Workbench can reconstruct similar outputs from source materials and identify gaps between AI-generated analysis and human research.
